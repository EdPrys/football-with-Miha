# Агент залучення організаторів Kopanka

Окремий TypeScript worker `apps/outreach`, не бот оголошень і не частина HTTP API.
Підготовлений для локального підключення Telegram; production-сервіс не створено.
Місто й групи не задані, акаунт не підключено, реальні повідомлення не надсилалися.

## Мета та поведінка

Головний результат — організатор провів першу реальну гру через Kopanka.
Воронка: знайдений кандидат → переглянутий/схвалений контакт → звернення →
відповідь → зацікавленість → підтверджена перша гра. Кількість повідомлень та
згода в переписці не вважаються активованими користувачами.

Агент читає лише задані групи, останні оголошення за 7 днів. Розпізнає саме
організаторів, які збирають людей на аматорський футбол у вибраному місті.
Потрібні прямий автор із публічним username та дослівне свідчення з оголошення.
Переслані пости, боти та дописи від імені каналів не використовуються як особисті
контакти. Агент не перебирає учасників груп і сам не вступає в нові групи.
Список кандидатів треба переглянути й схвалити для першого контакту. Дедуплікація
за Telegram user ID, перевірка відповідності username цьому ID перед читанням/відправкою.

Перше звернення фіксоване й представляє агента як помічника Kopanka. На пряме
питання агент чесно пояснює, що працює на основі ШІ. Типові відповіді працюють без моделі; для нестандартних питань OpenAI формує
коротку відповідь за перевіреними фактами
проєкту, допомагає зареєструватись, стати організатором і створити першу гру.
Посилання містить UTM кампанії. Агент не створює матч від імені співрозмовника,
не обіцяє гравців, прибутків, знижок чи бронювання поля. Тарифи платформи не
вигадує. Онлайн-оплат немає.

Без відповіді повторних звернень немає. Після відмови контакт закритий назавжди
для автоматичних звернень. Невизначені питання/скарги передаються власнику
(`handoff`), як і чати, де власник уже відповів вручну. Для існуючих переписок
перший автоматичний контакт не надсилається. Тексти співрозмовників та оголошень
не є інструкціями для агента; модель не має інструментів і не вибирає адресата.

За замовчуванням: dry-run, 3 нові контакти/день, 15 повідомлень/день, мінімум
5 хвилин між відправками, 30 модельних запитів/день, 15 000 фактично врахованих
токенів/день, до 3 модельних відповідей на контакт, до 10 перших контактів
за весь пілот, звернення 09:00–19:00
Europe/Kyiv. Це початкові операційні межі, не гарантія прийнятності контактів або
доставки. Усі Telegram обмеження/помилки зупиняють worker; обхід лімітів відсутній.
Після невизначеного результату відправки повторна автоматична спроба заборонена:
спочатку перевірити фактичний чат. Стан і квота записуються до мережевого виклику.

## Підготовка без акаунта і мережевих запитів

З кореня репозиторію:

```sh
pnpm --filter @app/outreach agent demo
pnpm --filter @app/outreach agent init
pnpm --filter @app/outreach agent check
```

`demo` використовує лише вигадані дані й mock-транспорт: знаходить кандидата,
проходить схвалення, перше звернення, відповідь і зупинку після відмови.
Жодних Telegram/OpenAI викликів чи оплати API в demo немає.

Дані за замовчуванням у `apps/outreach/.outreach/` (pnpm запускає команду з
каталогу пакета). Можна задати абсолютний `OUTREACH_DATA_DIR`. Файли не входять
у Git або Docker context. `config.json` створюється з `config.example.json`
і не перезаписується повторним `init`.

У конфігурації вкажіть місто, відомі групи `@username`, перевірений URL Kopanka
та назву UTM кампанії. Не змінюйте `mode: "dry-run"` до перевірки підключення.
`preview` показує перший текст без мережі. `check` не показує секретів.

## Коли буде телефон

Потрібні:

1. Telegram-акаунт і власні `api_id`/`api_hash` застосунку з
   [my.telegram.org](https://my.telegram.org/apps), а не токен бота оголошень.
2. OpenAI API key, назва доступної моделі з підтримкою Structured Outputs та
   межа витрат API-проєкту. Точна модель і бюджет ще не вибрані. Ліміт викликів
   worker не замінює ліміт витрат постачальника.
3. Місто, групи та перегляд першої добірки контактів/звернень.

Змінні з `apps/outreach/.env.example` передавайте через приватне середовище
процесу або захищений env-файл. CLI автоматично `.env` не завантажує. Не
надсилайте ключі, коди чи рядок Telegram-сесії у чат/репозиторій.

```sh
pnpm --filter @app/outreach agent connect
pnpm --filter @app/outreach agent check
pnpm --filter @app/outreach agent discover
pnpm --filter @app/outreach agent leads
pnpm --filter @app/outreach agent preview
pnpm --filter @app/outreach agent approve TELEGRAM_USER_ID
pnpm --filter @app/outreach agent run --once
```

`connect` виконується власником у приватному інтерактивному терміналі. Номер,
код та 2FA вводяться локально; код/пароль не відображаються. Сесія записується
у приватний файл. Підключення саме по собі не вмикає відправки.
`discover` і dry-run з відповідями вже викликають OpenAI, витрачають API квоту
й передають туди тексти оголошень/обмежену історію вибраних контактів. Вміст
інших особистих чатів не сканується. Responses викликається з `store: false`;
це не є обіцянкою нульового зберігання у постачальника.

Після перегляду результатів у конфігурації явно змініть `mode` на `live` і
запустіть `agent run`. Команда обробляє відповіді щохвилини й шукає нових
кандидатів щогодини, але нові кандидати не отримують повідомлень без `approve`.
Перший реальний тест — один схвалений контакт; лише після перевірки розширюйте
добірку. Під час запуску має бути рівно один worker із цим каталогом даних.

## Облік та керування

```sh
pnpm --filter @app/outreach agent report
pnpm --filter @app/outreach agent decline TELEGRAM_USER_ID
pnpm --filter @app/outreach agent activate TELEGRAM_USER_ID https://kopanka.pro/events/VERIFIED_EVENT_ID
pnpm --filter @app/outreach agent resolve-send TELEGRAM_USER_ID 'Чат перевірений власником'
pnpm --filter @app/outreach agent resume
```

`activate` — ручне підтвердження власником після перевірки реальної гри та її
організатора; повідомлення «я створив гру» від моделі не активує контакт. Цей
worker не має прямого доступу до production-БД. За окремим read-only токеном
можна отримати лише агреговані лічильники кампанії, як описано нижче.
Ці лічильники не встановлюють особу співрозмовника й не змінюють його статус
на `activated` автоматично.

Зупинка: Ctrl+C або SIGTERM. Команди роботи зі станом беруть той самий lock,
тому для перегляду/схвалення/паузи спершу зупиніть worker. `pause` записує
зупинку, `resume` знімає її, але не змінює dry-run/live. `resolve-send` прибирає
невизначений send після ручної перевірки й передає контакт власнику; автоматичного
повтору немає. Якщо процес завершено через SIGKILL, спершу переконайтеся, що
worker відсутній, потім приберіть лише `worker.lock`; `state.json` не видаляйте,
бо в ньому зберігаються відмови, історія й квоти. Резервні копії мають бути приватні.

## Постійний хостинг

`apps/outreach/Dockerfile` підготовлений для окремого Railway worker (build context —
корінь репозиторію). Його не підключено до автоматичних production-деплоїв.
Потрібен приватний persistent volume `/data/outreach`, конфігурація й сесія в ньому,
секрети лише в змінних Railway та одна репліка. Підготуйте volume/config/session
до запуску `run`. Публічний домен чи порт не потрібен. Не використовуйте
production API/database credentials: worker їх не потребує. Деплой і справжній
Telegram handshake ще не перевірені; це окремий крок під час підключення акаунта.

## Джерела протоколів

- [Telegram application credentials](https://core.telegram.org/api/obtaining_api_id).
- [Teleproto migration/API compatibility](https://docs.teleproto.dev/migrating-from-gramjs).
- [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).

## Короткий сценарій та економія

Базовий сценарій: 3–5 речень із користю для обох сторін, прямим переходом до
реєстрації/створення гри та запрошенням усієї компанії. Наступні відповіді —
1–3 речення, максимум 700 символів, не більше одного питання. Агент не проводить
анкетування щодо залу, університету, дати чи складу: організатор заповнює форму.
Нестандартні питання розглядаються окремо, без довгих повторних аргументів.

Перед моделлю оголошення проходять простий тематичний фільтр. Пріоритет отримують
регулярні ігри та організатори з власною групою. Відомі заперечення, згода,
підтвердження реєстрації й готове посилання на матч обробляються шаблонами.
Модель отримує останні 6 повідомлень по 800 символів і стислий контекст продукту.
Підготовлена відповідь зберігається: той самий dry-run, перезапуск або перехід
до live не генерує її повторно. Нова відповідь співрозмовника змінює контекст.

Облік `usage` зберігає фактичні `inputTokens`/`outputTokens`, а також виклики,
витрати яких постачальник не підтвердив (`unreportedUsageCalls`). Денний ліміт
перевіряється перед наступним запитом; останній запит може перевищити залишок.
Це не жорстка доларова межа: встановіть бюджет також у API-проєкті. Для оцінки
витрат задайте актуальні `OUTREACH_INPUT_USD_PER_MILLION` і
`OUTREACH_OUTPUT_USD_PER_MILLION` вибраної моделі. Без ставок або повних usage
сума буде `null`, а не вигаданим нулем. Оцінка не враховує кеш-знижки й не є рахунком.

## Реєстрації організаторів і гравців

Кожен контакт отримує випадковий ідентифікатор кампанії без Telegram username чи
user ID. Початкове посилання веде на реєстрацію з поверненням до створення гри.
На сторінці своєї гри організатор бачить «Запросити свою групу»: системне меню
або копіювання передає готовий короткий текст із закликом гравцям зареєструватись
і записатись. Для залучених організаторів посилання зберігає campaign UTM, щоб
врахувати реєстрації гравців тієї ж компанії.

Опційний API `POST /internal/outreach/metrics`:

- Вимкнений без `OUTREACH_METRICS_TOKEN`; токен має містити щонайменше 32 символи.
- `OUTREACH_CAMPAIGN_PREFIX` в API має збігатися з `campaign` конфігурації worker.
- Body — лише `{ "campaign": "organizers_pilot__0123456789abcdef" }`; окремий
  Bearer-токен читає тільки лічильники з дозволеним префіксом. Не використовуйте
  пароль БД, admin JWT або токен Telegram-бота.
- Відповідь: реєстрації кампанії, організатори, створені/завершені ігри, унікальні
  записані гравці без організатора, нові зареєстровані гравці, які записались,
  фактична участь та організатори з повторними створеними/завершеними іграми.
  Скасовані ігри й учасники, які вийшли, не входять до поточних показників.
- Жодних імен, email, телефонів, текстів чатів або user/event ID у відповіді немає.

У worker задайте `OUTREACH_METRICS_URL=https://<api-domain>/internal/outreach/metrics`
та той самий токен; `agent sync-metrics` оновлює звіт без виклику моделі.
`run` робить це щогодини, якщо налаштоване підключення. Помилка API не замінює
старі числа нулями: у звіті залишається час останнього спостереження.

Атрибуція ґрунтується на UTM під час реєстрації та може губитися через інший
пристрій/браузер, очищення сховища або інше джерело переходу. Вона не доводить,
що конкретний Telegram-контакт зареєструвався, і не охоплює вже зареєстрованих
користувачів, які прийшли без цієї signup-атрибуції. `playersJoined` у різних
групах може перетинатись; не підсумовуйте його як унікальних людей у всьому продукті.
Це поточний стан групи, а не незмінний журнал маркетингових подій.

Методика та джерела скілів: [OUTREACH_PLAYBOOK.md](OUTREACH_PLAYBOOK.md).
