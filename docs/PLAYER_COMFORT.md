# Звіт: зручність для гравців

Дата: 2026-11-03. Функції реалізовані локально; цей звіт не підтверджує деплой
або проведення дослідження з реальними гравцями.

## Що змінилося

1. **Контакти й дорога до поля.** Організатор добровільно додає телефон і/або
   Telegram username до конкретної гри при створенні або редагує їх на її сторінці.
   Форма попереджає, що контакти публічні. Особисті контакти з акаунтів не підтягуються.
   Маршрут використовує відомі координати або адресу комплексу; якщо їх немає,
   відкривається пошук майданчика за назвою й містом, без вигаданих координат.
2. **Підтвердження участі.** Картка «Ти записаний на гру» показує дату, час,
   команду й позицію. Вихід потребує другого натискання, його можна скасувати.
   Діє чинне правило бекенду: вихід не пізніше ніж за годину до початку;
   пізніше сторінка пояснює необхідність зв'язатися з організатором.
3. **Календар і добровільне нагадування.** Записаний гравець може завантажити
   `.ics` та окремо ввімкнути одне нагадування у Kopanka. Scheduler перевіряє
   кожні 5 хвилин і надсилає його протягом години до початку. Це не push/email,
   застосунок має бути відкритий для перегляду сповіщень. У календарному файлі
   автоматичного alarm немає: користувач налаштовує його у своєму календарі.
   Файл — знімок гри; він не синхронізує подальше скасування або зміни.
4. **Лист очікування.** Лише для заповненої майбутньої гри й після явного opt-in.
   Коли гравець виходить або додається команда, всі, хто очікує, отримують
   внутрішнє сповіщення. Це не FIFO-бронювання: місце не резервується,
   автоматичного запису немає. Потрібно відкрити гру й обрати вільну позицію.
   Відписка доступна на сторінці гри; успішний запис прибирає користувача з листа.
5. **Пам'ять і відновлення.** Місто й фільтр дати зберігаються в браузері;
   URL містить вибрані значення та підтримує повернення назад/пересилання.
   Форма нової/повторної гри зберігає основні поля у чернетку окремо для акаунта
   й джерела повторення. Чернетку можна очистити; успішне створення її видаляє.
   Запрошення треба обрати заново після перезавантаження. Паролі не зберігаються.
   При блокуванні localStorage форма працює, але відновлення після перезавантаження
   недоступне. Помилки входу, створення та завантаження мають зрозумілий текст
   і повторну дію; сторінка гри зберігає останні дані при помилці фонового оновлення.
6. **Сценарій перевірки на телефонах.** Підготовлено [USABILITY_TEST.md](USABILITY_TEST.md).
   Реальних гравців не залучали; візуальний прогін не виконано через помилку
   запуску сервісу керування Mac (Sky Computer Use service startup request failed).

## Надійність і доступ

- Запис, вихід і додавання до листа очікування узгоджені через блокування рядка
  Event у транзакціях. Два гравці не можуть зайняти одне останнє місце.
- Нагадування та позначка його відправлення записуються однією транзакцією
  під тим самим event lock. Одночасні scheduler-процеси не створюють дубль.
- Нагадування вимкнене за замовчуванням, вихід із гри його вимикає.
  Перезапис на гру створює новий цикл opt-in; перемикання off/on після вже
  надісланого нагадування не надсилає друге.
- Приватні reminder flags не повертаються у публічних учасниках гри.
  `events.myState` читає налаштування тільки поточного користувача.
- Контакти змінює лише організатор конкретної гри; введення перевіряється на сервері.

## Перевірки

- `pnpm test`: **180 тестів пройшли** (db 4, domain 129, API 26, web 21).
- `pnpm typecheck`: усі пакети пройшли.
- ESLint для зміненого коду пройшов.
- `pnpm --filter @app/web exec next build --webpack`: успішна production-збірка.
- Окрема локальна PostgreSQL-база: всі міграції з нуля; повторний opt-in листа
  очікування; вихід і сповіщення; конкурентні записи на останнє місце;
  одночасні scheduler-запуски; відсутність повторного нагадування; права на
  контакти та приватність API — пройшли. Тестові дані й базу прибрано.
- Візуальна перевірка iOS/Android та тест із реальними гравцями: **не виконані**.
  Імпорт `.ics` у конкретні календарні застосунки також потребує ручної перевірки;
  формат і екранування перевірені автоматично за [RFC 5545](https://www.rfc-editor.org/rfc/rfc5545).

Додатково виконано ширший прогін із 14 акаунтами через реальний HTTP/tRPC
transport: 18 етапів, 154 запити, 35 очікуваних відмов. Звіт і повторення:
[FULL_JOURNEY.md](FULL_JOURNEY.md). Браузерний UI цей прогін не охоплює.

## Локальне повторення інтеграційної перевірки

Потрібен локальний Postgres із docker-compose. Тест відмовляється працювати
з нелокальною адресою або БД, назва якої не починається на `kopanka_comfort_test`.
Команди нижче створюють окрему порожню тестову БД; основну БД не використовують.

```sh
docker exec football-postgres createdb -U football kopanka_comfort_test
DATABASE_URL='postgresql://football:football@localhost:5432/kopanka_comfort_test?schema=public' pnpm --filter @app/db migrate:deploy
INTEGRATION_DATABASE_URL='postgresql://football:football@localhost:5432/kopanka_comfort_test?schema=public' pnpm --filter @app/api exec tsx scripts/check-player-comfort.mts
# Після завершення перевірки видаліть лише цю тимчасову тестову БД:
docker exec football-postgres dropdb -U football kopanka_comfort_test
```

## Реліз

Потрібна міграція `20261103150000_player_comfort` до запуску нового API.
На локальній базі її застосовано. Docker CMD API вже виконує `migrate deploy`.
Після оновлення потрібен перезапуск API та rebuild web; scheduler живе в процесі API.
Зовнішні канали доставки не додавалися. Результати тесту не підтверджують
стан production або реальне отримання сповіщень його користувачами.
